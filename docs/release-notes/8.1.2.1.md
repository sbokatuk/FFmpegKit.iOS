## What's changed

First release under the `FFmpegKit.Net.*` package IDs, and the first built on FFmpeg **8.1.2** — the previous packages were labelled `4.5.1` but actually contained an FFmpeg **6.0** build. If you are coming from `FFmpegKit.FullGpl.iOS` or `FFmpegKit.Video.iOS`, read the breaking changes below before upgrading.

> **Package versions are `<ffmpeg version>.<binding revision>`.** `8.1.2.1` is FFmpeg `8.1.2`, binding revision `1`. The [Android bindings](https://github.com/sbokatuk/FFmpegKit.Android) number their packages differently, so the two repositories' versions are not comparable — a higher number there does not mean newer FFmpeg.

## ⚠️ Breaking changes

**Package IDs have changed.** `FFmpegKit.<Variant>.iOS` is replaced by `FFmpegKit.Net.<Variant>.iOS`, matching the [Android bindings](https://github.com/sbokatuk/FFmpegKit.Android).

```diff
-<PackageReference Include="FFmpegKit.FullGpl.iOS" Version="4.5.1-beta2" />
+<PackageReference Include="FFmpegKit.Net.FullGpl.iOS" Version="8.1.2.1" />
```

`8.1.2.1` is FFmpeg **`8.1.2`**, binding revision **`1`**. The fourth component belongs to this repository and increments when the bindings or packaging change while the native binaries stay put.

The `Ffmpegkit.Ios` namespace is **unchanged**, so your `using` directives and call sites stay exactly as they are. The namespace deliberately does not follow the package name: a namespace rooted at `FFmpegKit` containing a type also called `FFmpegKit` would make `FFmpegKit.Execute(...)` resolve the namespace instead of the class and fail to compile. The assembly is now `FFmpegKit.Net.<Variant>.iOS`, which only matters if you reference it by assembly name or via reflection.

**Licence metadata has been corrected.** The old packages declared `MIT`, which was wrong: they embedded a full-GPL native build. Packages now declare what they actually contain:

- non-GPL variants → `MIT AND LGPL-3.0-only`
- `-gpl` variants → `MIT AND GPL-3.0-only`

Your obligations have not changed — the metadata was simply inaccurate before. If you shipped the old `FFmpegKit.FullGpl.iOS` in a closed-source app on the basis of its `MIT` declaration, review that now. Each package ships the applicable texts under `licenses/`.

**Earlier `6.0.0.1-beta1` prereleases are superseded.** Seven of the eight `FFmpegKit.Net.*.iOS` ids carry a `6.0.0.1-beta1` published under a numbering scheme that no longer applies. They have been unlisted — nuget.org does not allow prereleases to be deleted, so they remain resolvable by exact version, but nothing should reference them. Move to `8.1.2.1`.

**FFmpeg itself jumped from 6.0 to 8.1.2.** Expect upstream FFmpeg behaviour changes across two major versions — filter syntax, defaults and codec availability may differ from what your commands relied on.

## Added

**All eight variants are now published**, not just `FullGpl`. `FFmpegKit.Video.iOS` previously existed only as an empty placeholder. Pick the smallest variant that covers your commands, and prefer a non-GPL one unless you need x264/x265/xvid/vidstab.

**Three target frameworks**: `net8.0-ios18.0`, `net9.0-ios18.0` and `net10.0-ios26.0`.

**A much larger API surface.** The previous binding was generated from `FFmpegKit.h` alone, which does not transitively include most of the library, so it exposed only 7 types. `FFmpegKitConfig`, `FFprobeKit`, `FFprobeSession`, `MediaInformation`, `MediaInformationSession`, `MediaInformationJsonParser`, `StreamInformation`, `Chapter`, `Packages` and `ArchDetect` were all missing and are now bound.

**`Task`-based APIs.** `FFmpegKit.ExecuteAsync` and `ExecuteWithArgumentsAsync` return `Task<FFmpegSession>` and accept a `CancellationToken` wired to the session's own cancellation; `FFprobeKit.GetMediaInformationAsync`, `ExecuteAsync` and `ExecuteWithArgumentsAsync` return tasks too. Previously the only asynchronous form was the native completion callback, so every caller wrapped the blocking `Execute` in `Task.Run`:

```diff
-var session = await Task.Run(() => FFmpegKit.Execute(command));
+var session = await FFmpegKit.ExecuteAsync(command, cancellationToken);
```

Cancelling asks FFmpeg to stop; the session then completes with a cancelled return code rather than throwing, and a partial output file may exist. There is no cancellation overload for probes — cancellation in FFmpegKit is an FFmpeg-session concept.

**Small ergonomic helpers.** `session.Succeeded()` and `session.Cancelled()` answer false for a session with no return code yet, instead of throwing. `FFmpegKitConfig.GetLogLevel()`/`SetLogLevel(Level)` and `log.Severity()` expose the bound `Level` enum where the native signatures use `int`, and `FFmpegKitConfig.IsLtsBuild` is a `bool` where the native `isLTSBuild` returns `int`.

Callbacks can now be **disabled** as the native API documents. `FFmpegKitConfig.EnableLogCallback`, `EnableStatisticsCallback` and the three session-complete equivalents accept `null` to clear a previously registered callback — the headers describe this ("or nil to disable a previously defined log callback"), but it was unreachable from C# without it.

## Known gaps

`MediaKeyMediaProperties` is **not** bound. `MediaInformation.h` declares the constant, but the compiled library never defines it, so binding it makes the *consuming* app fail to link with an undefined-symbol error. The nearest usable constant is `MediaInformation.KeyFormatProperties`. This will be bound if upstream starts exporting it.

The FFmpegKit wrapper API these bindings expose is older than the one the Android bindings wrap, so a few members added upstream after it have no counterpart here.

## Notes

The native binaries come from a different upstream than the Android bindings do — see [Where the native binaries come from](../../README.md#where-the-native-binaries-come-from). The two repositories therefore wrap different upstream builds: their package numbers are not comparable, and their APIs are not identical.

The macOS slice shipped in each upstream xcframework is stripped, since it is unreachable from a `net*-ios` binding. No Mac Catalyst slice is published upstream at all.
