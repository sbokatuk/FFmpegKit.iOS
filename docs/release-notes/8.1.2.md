## What's changed

First release under the `FFmpegKit.Net.*` package IDs, and the first built on FFmpegKit **8.1.2** — the previous packages were labelled `4.5.1` but actually contained an FFmpeg **6.0** build. If you are coming from `FFmpegKit.FullGpl.iOS` or `FFmpegKit.Video.iOS`, read the breaking changes below before upgrading.

## ⚠️ Breaking changes

**Package IDs have changed.** `FFmpegKit.<Variant>.iOS` is replaced by `FFmpegKit.Net.<Variant>.iOS`, matching the [Android bindings](https://github.com/sbokatuk/FFmpegKit.Android).

```diff
-<PackageReference Include="FFmpegKit.FullGpl.iOS" Version="4.5.1-beta2" />
+<PackageReference Include="FFmpegKit.Net.FullGpl.iOS" Version="8.1.2" />
```

`8.1.2` is FFmpegKit **`8.1.2`**. A fourth component, when present, belongs to this repository and increments when the bindings or packaging change while the native library stays put — `8.1.2.1` is still FFmpegKit `8.1.2`.

The `Ffmpegkit.Ios` namespace is **unchanged**, so your `using` directives and call sites stay exactly as they are. The namespace deliberately does not follow the package name: a namespace rooted at `FFmpegKit` containing a type also called `FFmpegKit` would make `FFmpegKit.Execute(...)` resolve the namespace instead of the class and fail to compile. The assembly is now `FFmpegKit.Net.<Variant>.iOS`, which only matters if you reference it by assembly name or via reflection.

**Licence metadata has been corrected.** The old packages declared `MIT`, which was wrong: they embedded a full-GPL native build. Packages now declare what they actually contain:

- non-GPL variants → `MIT AND LGPL-3.0-only`
- `-gpl` variants → `MIT AND GPL-3.0-only`

Your obligations have not changed — the metadata was simply inaccurate before. If you shipped the old `FFmpegKit.FullGpl.iOS` in a closed-source app on the basis of its `MIT` declaration, review that now. Each package ships the applicable texts under `licenses/`.

**FFmpeg itself jumped from 6.0 to 8.1.2.** Expect upstream FFmpeg behaviour changes across two major versions — filter syntax, defaults and codec availability may differ from what your commands relied on.

## Added

**All eight variants are now published**, not just `FullGpl`. `FFmpegKit.Video.iOS` previously existed only as an empty placeholder. Pick the smallest variant that covers your commands, and prefer a non-GPL one unless you need x264/x265/xvid/vidstab.

**Three target frameworks**: `net8.0-ios18.0`, `net9.0-ios18.0` and `net10.0-ios26.0`.

**A much larger API surface.** The previous binding was generated from `FFmpegKit.h` alone, which does not transitively include most of the library, so it exposed only 7 types. `FFmpegKitConfig`, `FFprobeKit`, `FFprobeSession`, `MediaInformation`, `MediaInformationSession`, `MediaInformationJsonParser`, `StreamInformation`, `Chapter`, `Packages` and `ArchDetect` were all missing and are now bound.

## Notes

The native binaries come from a different upstream than the Android bindings do — see [Where the native binaries come from](../../README.md#where-the-native-binaries-come-from). The Android packages track FFmpegKit `8.1.7`; the iOS ones track `8.1.2`. The two version lines are not expected to match.

The macOS slice shipped in each upstream xcframework is stripped, since it is unreachable from a `net*-ios` binding. No Mac Catalyst slice is published upstream at all.
